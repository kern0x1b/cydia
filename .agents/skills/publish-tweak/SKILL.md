# Publish a tweak to this Cydia repo

1. Build the `.deb` in the tweak's own source repo first (see that repo's
   README). This repo never builds tweak source — it only distributes
   already-built `.deb`s. Where the `.deb` lands depends on the repo:
   - `build.sh` repos write `dist/`;
   - charon/xmake repos write `build/` (`xmake deb`; `xmake deb -o DIR`
     writes to `DIR` instead).

2. From this repo's root, copy the deb in and reindex in one step:
   ```
   ./publish.sh <tweak-repo>/dist/<package>.deb     # build.sh repo
   ./publish.sh <tweak-repo>/build/<package>.deb    # xmake repo
   ```
   Run `./publish.sh` with no arguments instead if the `.deb` is already in
   `debs/` and you only need to reindex.

   This copies the file into `debs/`, regenerates `Packages`, `Packages.gz`,
   `Packages.bz2`, and rewrites the checksum block in `Release`. It prints
   every package/version it indexed — check that output names what you
   expect before committing.

3. If this is a new package (not just a version bump), read the
   `Depiction:` and `Icon:` fields of its control file:
   ```
   grep -A20 '^Package: <package-id>$' Packages | grep -E '^(Depiction|Icon):'
   ```
   The files you add must carry exactly the names those URLs end in — they
   are not derived from the package id (`com.kern0x1b.telegram` points at
   `depictions/classicgram.html` and `icons/classicgram.png`). Copy an
   existing page in `depictions/` as a template (it links `style.css` and the
   icon). Not every package has its own icon: a package whose `Icon:` names
   `CydiaIcon.png` (as `space.kern0x1b.soundcloudfix` does) needs nothing in
   `icons/`.

4. Add or update the row for the package in the README's "Published
   packages" table.

5. Commit everything together:
   ```
   git add -A
   git commit -m "Publish <Tweak Name> <version>"
   ```
   Match the existing commit style: a plain imperative subject, no type
   prefix, naming the tweak and version for a publish commit.

6. Pushing publishes: GitHub Pages serves `main` to every device that has
   the source. Show the owner the indexed package list and the commit, and
   run `git push` only after the owner confirms.

## Traps

- Never hand-edit `Packages` or the checksum block in `Release` — both are regenerated by `publish.sh` and any manual edit is overwritten on the next run.
- A depiction or icon named after the package id instead of the control file's URL is a 404 in Cydia.
- Never delete an older `.deb` from `debs/` — the index keeps every version.
